01 · Freeze the architectural truth

Start with the envelope, not a pile of prefabs.

The baseline probe solved one accepted interpretation of tn0304, then exported that interpretation as an immutable, hash-verified capsule. That boundary mattered: Studio could inspect and place the result, but it could not quietly reinterpret the architecture.

02 · Carry enough, and only enough

A capsule, not a second design system.

The ZIP carried the solved graph, constraints, interpretation and compilation receipts, compiled pieces, the architectural candidate capture, and only the prefab geometry needed to render those pieces. Every member was listed, sized, and hash-pinned.

That kept the handoff ruthless. There was no general CAD solver in Studio, no dimension editing, no prefab catalog, and no imported code to execute. Rebuilding identical inputs produced byte-identical capsule bytes.

Immutable by construction

  • Traversal, duplicate, unlisted, oversized, or tampered members fail before persistence.
  • Graph, receipts, capture, and piece counts must reconcile.
  • The accepted adaptation is exactly 16 floors, 16 walls, and 8 roofs.
  • Placement remains revision-checked metadata; canonical bytes never drift.
03 · Make the adaptation inspectable

Studio showed both kinds of truth.

Architecture mode kept the footprint, wall datum, ridge, roof planes, classifications, provenance, conflicts, and 29 mm reconciliation visible. Game pieces mode showed the exact normalized prefabs Studio would stage. The creator could compare intent with adaptation without pretending they were the same thing.

04 · Learn without reconstructing

The useful part of R&D mode was what it stopped doing.

The cold acceptance replay had already done the responsible destructive test: the canonical pair was built, proved, and cleared, then the exact pre-run machine state was restored. That established reversibility. It was also the wrong loop for every remaining visual and integration question.

Cold acceptance

Launch, enter, check, apply all 40 pieces, diff MATCH, clear all 40, stop, and restore exact plugin, Runtime, Lab, world, and character bytes.

Warm creation

The accepted structure was built once and deliberately left standing. Creator build mode was turned back off; rollback remained explicit and available.

Warm inspection

The next operator pass reused the canonical stage, control plane, running client, loaded world, and one retained build. Forty pieces still matched exactly.

Yes—R&D mode helped.

Not as a vague productivity claim. It cut the final lap to five read-only operations, preserved the accepted scene for human inspection, and made integration defects cheaper to isolate.

05 · The scars that earned the lap

Warm reuse found seams the happy path hid.

None of these were architectural failures. They were boundary failures—the exact kind a vertical slice is supposed to flush out before a demo.

The verifier expected a cold client.

The original machine guard treated an already-running Valheim process as drift. Warm mode now requires the same process identity and command line, keeps world, character, session, and mailbox bytes strict, and permits only append-only event archive growth.

A GET acquired an empty body.

Windows PowerShell’s request path attached a body where the host expected none. Empty strings are now treated as no body, making the operator path agree with the API contract.

The receipt told the wrong sequence.

The demo index initially lifted operations from a summary instead of the detailed warm sequence. The final receipt now records the exact five operations and explicitly pins stage and control-plane reuse.

06 · Review after the adrenaline

A convincing slice, with sharp edges still visible.

The result is demoable because the evidence chain is coherent, not because the prototype suddenly became a product. The distinction is worth protecting.

What is proven

  • The accepted envelope exports deterministically and imports immutably.
  • Architectural intent and exact game adaptation can be inspected side by side.
  • Placement metadata does not alter canonical artifacts.
  • The staged pair applies as 40 buildable pieces and diffs MATCH.
  • A warm read-only lap can reuse the accepted structure without teardown.

What is not generalized

  • This remains a hard-pinned tn0304 vertical slice, not a general CAD or prefab workflow.
  • The harness is intentionally machine-aware and should become fixture-driven only when a second structure earns that abstraction.
  • The largest Studio and live-probe files should be split before broader product work.
  • The game capture is operational evidence, not a cinematic camera pass.
