## Where things stand

Lane 0 of the Creator OS build strategy is **closed**. Its job was narrow and it is done:

> untrustworthy roadmap + healthy implementation
> → **trustworthy roadmap + known implementation gaps**
> → implementation.

That second state is where you are now. The roadmap no longer misreports itself, and the
implementation gaps are named in a ledger rather than discovered one at a time.

The conclusion the whole program rests on still holds, and it is good news:

> **The remaining work is smaller than the roadmap makes it look, because the contract layer
> is consistently ahead of the runtime layer.**

`QuestPackStore.InspectLane` already validates, hashes, and compiles *N* experience documents.
Reset and rerun are wired end to end — endpoints, service, store, browser UI, file mailbox,
Runtime poller. The bounded request/receipt mailbox pattern exists in three tested flavours.
What is missing is usually one refusal, or live evidence, not a subsystem.

Read [`retros/2026-08-25-a-gate-you-walk-yourself.md`](retros/2026-08-25-a-gate-you-walk-yourself.md)
before trusting your own verification of anything here. Its one change is small and it is the
difference between a gate and a decoration: before reporting that a property is enforced, make
the negative case and watch it fail.

Three records constrain what you may quietly change:
[ADR 0015](adr/0015-the-requirements-ledger-cannot-confer-lane-authority.md) (the ledger records
lane authority and cannot confer it),
[ADR 0016](adr/0016-evidence-retention-archives-it-never-silently-deletes.md) (retention archives

## The next executable task

**Lane 4 — drive the real `4A / guild-scale-runtime` exit and call the seat.** This is where the
program has been heading, and it is the first step that cannot be taken without the installed
game. Lanes 0, 1 and 2 are done; Lane 3 was a decision lane and both its rulings are recorded
([ADR 0014](adr/0014-one-human-launch-and-entry-is-the-baseline.md),
[ADR 0012](adr/0012-creator-session-world-entry-is-not-field-lab-orchestration.md)).

`queue.full-width-journey` is the work item: state `gated`, lane `4A`, claiming `FR-LOOP-001`,
`NFR-SEAT-001`, `NFR-SEAT-003`, `NFR-TEST-001`. The exit it has to satisfy is
`creator-os-phases.json`'s 4A `exit`, and the human boundary is exactly one action — launching
the game and entering the pinned authoring world. Everything after entry is machine-owned. Read
`NFR-SEAT-003` before booking any seat time: the gate may begin only after automation has driven
every applicable step, collected the evidence, and fixed and rerun the mechanical failures.

**Three things are built and unproven, and Lane 4 is what turns that around.** `queue.portfolio`,
`queue.reset`, `queue.guild-runtime` and `queue.receipt-retention` are all `implemented` — code
exists, contract-tested, no installed game has exercised it. That state is not a synonym for
done, and reporting it as done is the specific failure this repository has paid for.

### Lane 2 landed 2026-08-25 — implemented, not proven

Audit C3 in both directions, from `NFR-OBS-001`.

- **Run-control receipts are partitioned by run.** They sat in one flat directory keyed by request
  id, and pruning ordered *all* of it by write time and deleted the tail — so a burst of resets on
  one run silently evicted an older run's receipts, the exact clause the requirement forbids. The
  cap is now 32 per run rather than 128 shared, against a registry that keeps up to 512 runs with
  predecessor lineage.
- **`RuntimeReceiptStore` has retention at all.** It had no cap, no prune, and `List()` enumerated
  and sorted every file on each call. Live window: 512 receipts or 30 days, swept every 64 writes
  so the game loop never pays per write.
- **Archiving moves the exact bytes.** A store read back as authority may not change the shape of
  its evidence at a retention boundary, so nothing is destroyed there — archived receipts are the
  same files in `receipts/archive/`, and `ListArchived` reads them.
- **The one place evidence is destroyed says so.** Past the archive bound, a
  `receipt_archive_evicted` receipt names the count and the time range. A gap in a correlated
  proof set is a fact you can read rather than something to infer from absence.
- `select_experience` receipts have no run, so they share a bounded `pack` partition. A scope may
  not escape its directory: run ids are `Safe()` identifiers and that policy admits `.` and `..`,
  which are safe as names and not as path segments.

Lane 2 had to land before Lane 4 collects the 4A evidence, or that evidence would be written to a
store that can drop members of a correlated proof set. That ordering is now satisfied.

relevant, but scheduling needs a ruling nobody has made.** Every one names its missing
decision in `pending_ruling`. The authoritative list is
[`creator-requirements-ledger.json`](creator-requirements-ledger.json); these are the ids, so

An agent may not resolve one of these by picking the obvious lane. That is the specific
failure the ledger's one-way lane authority exists to prevent: every lane it names points at
where the lane came from, and neither source is the ledger.

`queue.workbench-boundary` is the same ruling wearing a work item: state `ready`, lane
`unassigned`, with a `lane_note` naming the open question. Ready and unassigned at once is
information — technically executable, not selected as next work, pending a named ruling — not
a queue defect to normalize away.

## Environment gotchas that will cost you time

- **The interim package trap (D6).** `Comfy.Quest.Contracts.0.6.0-local.nupkg` was repacked
  without a version bump, so a warm NuGet cache serves stale contracts under the same version
  string. A plain `dotnet test src/Quest.Studio.Tests` fails with `CS0246` on
  `RuntimeRunControlReceipt` / `RuntimeRunStatusEntry` / `RuntimeRunStatusStore`. Set
  `NUGET_PACKAGES` to a directory keyed to the nupkg hash, the way
  `tools/quest-studio/Start-QuestStudio.ps1` already does. CI is unaffected — it restores clean.
  **Live instance:** the Lane 1 contracts change repacked that package again without a version
  bump, because bumping it is punch item 16 and item 16 is parked. A warm cache will therefore
  compile Studio against contracts with no `ActiveSet.ExperienceId` and fail on the selector.
- Host `dotnet` is 8.0; .NET 9 lives at `C:\work\dotnet9\dotnet.exe`. `Quest.Studio*` targets
  net9.0.
- The Creator Session tests spawn real `powershell.exe` (5.1). No `&&`, and
  `Get-Content`/`Set-Content` round trips corrupt UTF-8. `Get-FileHash` is unresolvable on the
  hosted runner for reasons outside this repository — hash through
  `System.Security.Cryptography.SHA256` instead.
- **A worktree isolates the repository, not the game install.** Agree who owns
  `<Valheim>/BepInEx/` before any lap. Two separate incidents came from not doing this.
